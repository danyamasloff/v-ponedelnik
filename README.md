# yan-channel-factory

Data-driven платформа для выбора ниши, запуска и монетизации Telegram/MAX-каналов.

Сначала система учится отвечать на вопрос **«какую нишу запускать»** на основании
рыночных данных, и только потом автоматизирует производство контента.

**Текущий статус: работает конвейер публикаций.** PostgreSQL и миграции, импорт
рыночных выгрузок, аналитика ниш с Niche Score v1, анализ конкурентов, автономный
движок исследований (источники, дедупликация в события, Topic Score v1, учёт
расходов на LLM), генерация текста поста, локальный рендер карточек и постинг в
MAX по расписанию — три слота в день с двумя выключателями безопасности.

Не сделано: fact check черновиков, метрики опубликованных постов, Telegram.

Ниша выбрана: **практические AI и цифровые навыки** для работы, учёбы и
повседневных задач; бренд планируется в Telegram и MAX одновременно.

## Требования

| Компонент | Версия на машине разработки |
|---|---|
| uv | 0.12+ (сам ставит нужный Python 3.12) |
| Docker Desktop | 29+ (нужен только для PostgreSQL) |
| Git | 2.54+ |

Python-приложение работает локально в Windows, в контейнере крутится только база —
так проще отлаживать.

> **Про `python -m`.** На этой машине Windows Application Control блокирует
> `.exe`-шимы из `.venv\Scripts` (`alembic.exe`, `pytest.exe`, `ruff.exe`).
> Поэтому все инструменты запускаются как модули: `uv run python -m alembic …`.
> Это единственный рабочий вариант здесь; на машине без такой политики короткая
> форма `uv run alembic …` тоже сработает.

### Импорт выгрузки

Реальные выгрузки кладутся в `data/raw/direct/` (каталог в `.gitignore`).

```bash
uv run python -m channel_factory.cli import-direct data/raw/direct/export.xlsx
```

Полезные опции:

* `--force` — импортировать файл повторно как новый прогон (по умолчанию файл с
  тем же SHA-256 пропускается);
* `--snapshot-date 2026-09-01` — дата снимка для файлов без колонки с датой
  (по умолчанию — сегодняшняя дата UTC);
* `--source "Каталог каналов"` — метка источника данных;
* `--sheet "Лист2"` — конкретный лист XLSX.

Поведение при проблемах в данных:

* нет обязательной колонки с названием канала → импорт **падает целиком** с
  понятной ошибкой, ничего не записывается;
* строка без названия канала → строка **отклоняется**, импорт продолжается;
* нераспознанное число/дата/URL → **предупреждение**, поле пишется как `NULL`,
  исходное значение сохраняется в `raw_data`.

Ничего не удаляется молча: и отклонённые строки, и предупреждения хранятся
в `direct_import_rows` и видны через `show-import`.

### Анализ ниш

```bash
uv run python -m channel_factory.cli analyze-niches --report
```

Команда считает робастную статистику по нишам (медианы, квартили, концентрация
топ-каналов, рост между датами), вычисляет Niche Score v1 и сохраняет прогон в
базу. `--report` дополнительно пишет файлы в `reports/`.

Опции: `--as-of 2026-09-01` (считать по снимкам не позднее даты),
`--no-persist` (посчитать, не сохраняя прогон).

Пример вывода:

```
 #   SCORE  КАНАЛОВ  НИША
------------------------------------------------------------
 1    71.6        5  AI и технологии
 2    46.0        3  Финансы
 3    41.5        4  Маркетинг
 4    40.4        4  Карьера и IT
    пропущена: Игры (каналов: 2)
```

Что важно понимать про эти числа:

* Score — **инструмент сравнения ниш между собой**, а не абсолютная оценка;
  читать его нужно вместе с разбивкой по компонентам в отчёте.
* Компоненты, которые нельзя посчитать на текущих данных, исключаются, а веса
  перенормируются — пропуски не заполняются выдуманными значениями.
* Пять компонентов — субъективные оценки. Пока они не заданы в
  `config/niche_score.yaml`, используется нейтральное значение 50, и они не
  различают ниши. CLI и отчёты об этом предупреждают.
* Если данных нет, команды печатают `NO DATA` и ничего не выдумывают.

Подробности формулы — в [docs/niche-score.md](docs/niche-score.md).

### Публикация в MAX

Адаптер для постинга в каналы MAX через официальный Bot API. Бесплатно:
платных тарифов у Bot API нет. Сделан раньше своей фазы — чтобы можно было
проверить публикацию на живом канале.

```bash
uv run python -m channel_factory.cli max-post "Текст поста" --dry-run
```

`--dry-run` показывает готовое тело запроса и не отправляет ничего — работает
даже без токена. Для реальной публикации нужны `MAX_BOT_TOKEN` и `MAX_CHAT_ID`
в `.env`, бот должен быть администратором канала; `max-check` проверяет это до
первого поста, а `max-discover` подсказывает `chat_id`.

Подробности — в [docs/max-publishing.md](docs/max-publishing.md).

### Три поста в день

Конвейер `research → черновик → разбор → карточка → слот` описан в
[docs/posting-pipeline.md](docs/posting-pipeline.md). Коротко:

```bash
uv run python -m channel_factory.cli publish-plan --days 3
```

```bash
uv run python -m channel_factory.cli publish-due
```

Две дорожки: новости из источников и **собственные посты** из
`config/evergreen_topics.yaml` — без ссылок и без внешнего повода. Ссылка на
источник печатается только если читатель из России откроет её без VPN;
остальные источники указываются по имени, а смысл поста лежит внутри поста.

`publish-due` идемпотентна: в один слот уходит максимум один пост, поэтому её
можно звать по расписанию хоть каждый час. Пока `PUBLISH_MODE=DRY_RUN` или
`AUTO_PUBLISH_ENABLED=false`, конвейер проходит весь путь и ничего не
отправляет.

Разрез по платформам (единый бренд запускается в Telegram и MAX одновременно):

```bash
uv run python -m channel_factory.cli analyze-niches --platform TELEGRAM --report
```

```bash
uv run python -m channel_factory.cli cross-platform-niches
```

`cross-platform-niches` ранжирует ниши по **слабейшей** из двух платформ: единый
бренд не может быть сильнее своего слабого звена.

### Анализ конкурентов

```bash
uv run python -m channel_factory.cli show-niche tehnologii --report
```

Досье по нише: распределение подписчиков и ERR по квантилям, доля топ-10,
лидеры по подписчикам, по вовлечённости и по цене размещения, пороги входа.

Важное ограничение: выгрузка описывает, как канал **продаётся рекламодателю**
(аудитория, ERR, цена). Постов, частоты публикаций и заголовков в ней нет,
поэтому анализ контент-паттернов по этим данным невозможен и не делается.
Подробности — в [docs/competitor-analysis.md](docs/competitor-analysis.md).

## Разработка

```bash
uv run python -m pytest
```

```bash
uv run python -m ruff check .
```

Интеграционные тесты используют отдельную базу `channel_factory_test` — она
создаётся и мигрируется автоматически. Имя обязано заканчиваться на `_test`,
иначе тесты откажутся запускаться (защита от очистки рабочих данных).

Новая миграция после изменения моделей:

```bash
uv run python -m alembic revision --autogenerate -m "описание"
```

Схема БД меняется **только** через Alembic; `Base.metadata.create_all()` не
используется.

## Структура

```
src/channel_factory/
    core/        конфигурация, логирование, доменные enum'ы
    db/          модели, репозитории, сессии
    direct/      импорт выгрузок: mapping -> normalization -> importer
    publishers/  публикация постов: общий контракт + адаптер MAX
    cli/         команды Typer
alembic/         миграции
config/          бизнес-конфигурация (маппинг колонок)
data/raw/direct/ входные выгрузки (не коммитятся)
tests/           unit + integration
docs/            архитектура и формат импорта
```

## Безопасность

* Секреты только в `.env`, он в `.gitignore`; шаблон — `.env.example`.
* Пароль БД не попадает в логи: URL всегда маскируется (`masked_database_url`).
* `alembic.ini` не содержит строки подключения — URL берётся из `.env`.
* Реальные выгрузки из `data/raw/` не коммитятся.
