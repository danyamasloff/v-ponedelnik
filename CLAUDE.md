# CLAUDE.md

Инструкции для Claude Code по этому репозиторию.

## Что это

Локальная платформа для выбора ниши и запуска Telegram/MAX-каналов на основе
рыночных данных. Приоритет проекта сейчас — **рыночные данные и аналитика ниш**,
а не генерация контента, видео и не автоматизация публикаций.

**Текущая фаза: PHASE 4 завершена** — Autonomous Research Engine (источники,
дедупликация, кластеризация, Topic Score v1, учёт расходов на LLM).
Следующая — PHASE 5: Content Engine + Fact Check.

Ниша выбрана: **практические AI и цифровые навыки** для работы, учёбы и
повседневных задач; бренд запускается в Telegram и MAX одновременно.

В базе лежат **реальные данные**: каталог Яндекс Директа от 2026-09-02,
11 109 каналов (Telegram 5 640 / MAX 5 469), 36 категорий, один снимок.

Вне очереди сделан адаптер публикации в MAX (`publishers/`, команды `max-*`) —
по запросу владельца, чтобы проверить постинг на живом канале. Он без
persistence: таблиц публикаций нет и появятся они в своей фазе. Подробности —
[docs/max-publishing.md](docs/max-publishing.md).

## Архитектурные принципы

* Modular monolith. Не добавлять Kafka, RabbitMQ, Redis, Celery, Kubernetes,
  ClickHouse, Airflow и микросервисы без реальной проблемы, которую они решают.
  Если такая проблема появилась — сначала объяснить её, потом предлагать
  инструмент.
* Бизнес-логика живёт в domain services, а не в командах CLI и не в моделях.
* Repositories используются там, где реально прячут сложность запросов, а не
  ради абстракции.
* PostgreSQL — единственный source of truth. SQLite запрещён даже для тестов.
* Исторические данные только дополняются. Метрика никогда не обновляется на
  месте: новый замер = новая строка со своей датой.

## Правила миграций

* Схема меняется **только** через Alembic. `Base.metadata.create_all()` не
  использовать.
* Новая модель обязана быть импортирована в `src/channel_factory/db/models/__init__.py`,
  иначе autogenerate её не увидит.
* После autogenerate — прочитать сгенерированный файл. Alembic, в частности,
  **не удаляет PostgreSQL ENUM-типы** в `downgrade()`, это дописывается руками
  (пример — в первой миграции).
* Проверять обратимость: `alembic downgrade base` → `alembic upgrade head`.
* URL берётся из `.env`; в `alembic.ini` строки подключения быть не должно.

## Требования к тестам

* Unit-тесты для нормализации, маппинга колонок и любых чистых правил.
* Integration-тесты для конвейера импорта и репозиториев — против реального
  PostgreSQL, на отдельной БД `*_test` (создаётся автоматически).
* Не гнаться за процентом покрытия. Покрывать то, что ломается молча:
  разбор чисел, дедупликацию, идемпотентность.
* `pytest` и `ruff check .` должны проходить перед коммитом.

## Работа с данными

* Сырые значения источника сохраняются всегда (`raw_data`), нормализованные —
  отдельно. Не «чинить» данные молча.
* Ничего не выбрасывать без следа: отклонённые строки и предупреждения пишутся
  в БД и показываются в `show-import`.
* Demo/тестовые данные никогда не смешиваются с реальными и не выдаются за
  результат анализа рынка. Если данных нет — так и сообщать (`NO DATA`).
* Не выдумывать поля, которых нет в источнике.

## Аналитика и метрики

* Только робастная статистика: медиана и квантили, не среднее. Один гигантский
  канал не должен определять нишу.
* Недоступный компонент метрики исключается, а веса перенормируются. Пропуск
  никогда не заполняется нулём, средним или иным придуманным значением.
* Метрика, которая вырождается на малой выборке (например, доля топ-3 в нише из
  трёх каналов всегда равна 100%), должна становиться недоступной, а не давать
  ложный сигнал.
* Niche Score меняется только через новую версию (`niche_score_v2` = новый
  модуль расчёта + новое значение `score_version`). Старые прогоны не
  пересчитываются задним числом.
* Субъективные оценки помечаются как субъективные и по умолчанию нейтральны,
  чтобы не различать ниши незаметно для пользователя.
* Отчёты генерируются из **сохранённого прогона**, а не пересчитываются на лету,
  иначе файл разъедется с базой после нового импорта.

## Секреты

* Только `.env` (в `.gitignore`), шаблон — `.env.example` без значений.
* Никогда не логировать токены, пароли и «сырые» строки подключения; для URL
  использовать `masked_database_url`.
* Реальные выгрузки из `data/raw/` не коммитятся.

## Чего не делаем

* Накрутка подписчиков, просмотров, реакций и рекламных кликов.
* Плагиат контента.
* Обход CAPTCHA, anti-bot, авторизации и rate limits.
* Browser automation там, где задачу решает официальный API или экспорт.

## Автономный конвейер

* Claude Routines выполняются в облаке и **не имеют доступа** к локальной
  PostgreSQL. Они не входят в runtime и не являются source of truth; их место —
  еженедельные отчёты в репозиторий.
* Ни Telegram Bot API, ни MAX Bot API не дают доступа к постам чужих каналов.
  Обходить это нельзя: Telegram прямо запрещает scraping и агрегацию своих
  данных. Источник, отвечающий 403, отключается с причиной.
* Каждый LLM-вызов пишется в `ai_generations`; лимиты расходов проверяются до
  вызова и считаются суммой по этой же таблице. Неизвестная модель в прайсе —
  ошибка, а не нулевая стоимость.
* Opus в runtime не используется: Haiku — извлечение и классификация,
  Sonnet — синтез.
* Структурированный вывод — только через инструмент со `strict: true`.

## Внешние API

Telegram, MAX и Яндекс — **не по памяти**. Перед реализацией соответствующего
модуля сверяться с актуальной официальной документацией (для MAX —
<https://dev.max.ru/>). Если нужной возможности в API нет — сказать об этом, а
не придумывать endpoint.

Решения должны оставаться **бесплатными**: только те возможности API, которые
доступны без платных тарифов. Если задача решается лишь платной функцией —
сказать об этом прямо, а не подключать её молча.

## Стиль кода

* Python 3.12, `ruff` с настройками из `pyproject.toml`.
* Типизация там, где помогает; mypy намеренно не подключён, чтобы не превращать
  настройку typing в отдельный проект.
* Комментарии объясняют **почему**, а не пересказывают код. Особенно ценны
  комментарии к неочевидным решениям (например, разбору неоднозначных чисел).
* RUF001/002/003 отключены: кириллица в строках здесь — доменные данные.
