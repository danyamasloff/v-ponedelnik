# Конвейер публикаций: три поста в день

Цель конвейера — держать ритм канала: три поста в сутки без ручной работы.
Всё звено работает **бесплатно**: MAX Bot API без тарифов, картинки рисуются
локально, текст пишет либо локальная модель, либо бесплатный tier Gemini.

Две дорожки контента, и это осознанное разделение:

* **новости** — реакция на то, что произошло у вендоров;
* **свои посты** — материалы, которые мы пишем сами, без внешнего повода.

Канал, который только пересказывает чужие релизы, не имеет собственного голоса,
поэтому часть слотов зарезервирована под свои посты, а не отдана им по
остаточному принципу.

## Путь одного поста

```
research-poll → research-cluster → score-topics → publish-due
   источники      события            Topic Score    слот → пост
```

1. **research** собирает факты из whitelist-источников и схлопывает их в
   события (кластеры), считает Topic Score и отбирает лучшие (`SELECTED`).
2. **drafting** собирает скелет поста: заголовок, одна фактическая фраза из
   полей, которые мы извлекли сами, ссылка на первоисточник — и **маркер** на
   месте оригинального разбора.
3. **generation (PHASE 5)** пишет разбор и русский заголовок. Пересказ
   источника прямо запрещён промптом: это и бесполезно читателю, и плагиат.
4. **cards (PHASE 6)** рисует картинку 1200×630 локально через Pillow.
5. **publish-due** проверяет, открыт ли слот и не занят ли он, и публикует.

Скелет без разбора публиковать нельзя: `is_publishable` = False, издатель
возвращает `BLOCKED`. Это осознанный тупик — лучше пропустить слот, чем
выложить полуфабрикат.

## Аудитория читает из России

MAX — российская сеть. Из этого следуют два правила, которые зашиты в конвейер.

**Ссылку печатаем только ту, которую читатель откроет.** У каждого источника в
`config/research_sources.yaml` есть поле `audience_access`:

```
audience_access: RU   # ссылку печатаем
audience_access: VPN  # источник называем по имени, ссылку не печатаем
```

По умолчанию `VPN`. Считать иностранный источник доступным — та самая ошибка,
из-за которой в канале появляются ссылки в никуда: читатель нажимает и не
получает ничего, а потом перестаёт нажимать вообще.

**Смысл поста лежит внутри поста.** Раз ссылка может отсутствовать, пост обязан
работать сам по себе: заголовок, факт, разбор и конкретный шаг. Ссылка — бонус,
а не носитель ценности.

Российские источники в whitelist (проверены 2026-09-06, отвечают и парсятся):
Habr (хабы ИИ и машинного обучения), блоги Яндекса, Сбера и VK на Habr, Tproger,
RB.RU, CNews.

## Свои посты

`config/evergreen_topics.yaml` — список тем, которые мы пишем сами: без новости,
без источника, без ссылок. Тема описывается тремя полями — угол подачи, что
читатель унесёт и для кого это. Формулирует их человек: генератор, придумывающий
себе темы, — прямой путь к постам ни о чём.

Слоты для своих постов задаются индексами:

```
PUBLISH_OWN_SLOTS=1     # второй слот дня — наш
```

Своя тема также подставляется, когда у новостной дорожки ничего не осталось:
молчащий слот не помогает никому. Каждая тема публикуется один раз — учёт по
`publications.topic_key`.

Когда темы заканчиваются, `publish-plan` покажет `Своих тем: 0`, и это сигнал
пополнить файл, а не повод публиковать повтор.

## Срочные новости

Крупное событие не должно ждать следующего слота, поэтому перед проверкой слота
конвейер смотрит, нет ли «горячей» темы. Планка нарочно высокая — канал,
который кричит каждый день, читают как ленту:

```
BREAKING_MIN_SCORE=90          # только верх рейтинга
BREAKING_MAX_AGE_MINUTES=240   # событие свежее четырёх часов
BREAKING_MIN_SOURCES=2         # подтверждение: два источника…
                               # …или публикация самим вендором (OFFICIAL/PRIMARY)
BREAKING_MAX_PER_DAY=2         # потолок за сутки
BREAKING_MIN_GAP_MINUTES=90    # пауза после предыдущего поста
```

Требование подтверждения — не формальность. Один источник, даже с высоким
рейтингом, это ещё не событие: так в канал попадают слухи, а репутацию потом не
вернуть. `BREAKING_ENABLED=false` выключает механизм целиком.

## Только актуальное

Тема старше `PUBLISH_MAX_TOPIC_AGE_HOURS` (по умолчанию 48 часов) в плановые
слоты не идёт: устаревшая новость хуже её отсутствия — читатель делает вывод,
что канал отстаёт. Если свежих тем нет, слот берёт собственный пост, а если и
их не осталось, слот честно пропускается.

## Слоты и идемпотентность

Расписание не хранится в таблице. Слот считается занятым, если в его окне уже
есть публикация — источник правды тот же `publications`. Отсюда свойства:

* `publish-due` можно звать хоть каждые пять минут: в слот уйдёт максимум один
  пост;
* пропущенный запуск не теряет слот — окно `PUBLISH_SLOT_WINDOW_MINUTES`
  (по умолчанию 180 минут) даёт время наверстать;
* «симулированные» посты (`DRY_RUN`) тоже занимают слот, иначе репетиция вела
  бы себя не так, как боевой режим.

Настройки:

```
PUBLISH_SLOTS=09:00,14:00,19:00
PUBLISH_SLOT_WINDOW_MINUTES=180
```

## Два выключателя

```
PUBLISH_MODE=DRY_RUN        # DRY_RUN | LIVE
AUTO_PUBLISH_ENABLED=false  # главный рубильник
```

Оба по умолчанию выключены. Чтобы посты реально уходили в канал, нужно
`PUBLISH_MODE=LIVE` **и** `AUTO_PUBLISH_ENABLED=true`. В `DRY_RUN` конвейер
проходит весь путь, пишет строку в `publications` и не отправляет ничего.

## Кто пишет текст

| Бэкенд | Стоимость | Квота | Что уходит наружу |
|---|---|---|---|
| Ollama (локально) | бесплатно | нет | ничего |
| OpenAI-совместимый API | бесплатно в пределах tier | своя | заголовок, вендор, продукт, версия |
| Gemini free tier | бесплатно | **на модель, маленькая** | то же |
| нет бэкенда | — | — | посты остаются скелетами и не публикуются |

Выбор автоматический, в этом порядке: локальный Ollama (если отвечает и модель
скачана) → OpenAI-совместимый эндпоинт (если задан ключ) → Gemini.

### Gemini: квота считается по моделям

Замер от 2026-09-06 живым ключом:

```
Quota exceeded for metric: generate_content_free_tier_requests,
limit: 20, model: gemini-3.8-flash
quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier
```

Это **20 запросов в сутки на конкретную модель**, а не 1500, как было у старых
Flash. Но квота у каждой модели своя, поэтому клиент при таком 429 переключается
на следующую из `MODEL_FALLBACKS` (`gemini-3.1-flash-lite`,
`gemini-3-flash-preview`, ...), а не считает день потерянным. На трёх постах в
сутки этого хватает с запасом.

### OpenAI-совместимый эндпоинт (в том числе Qwen)

```
CONTENT_API_BASE_URL=https://dashscope-intl.aliyuncs.com/compatible-mode/v1
CONTENT_API_KEY=<ключ Model Studio>
CONTENT_MODEL=qwen-plus
```

Проверенные бесплатные варианты:

* **Qwen через Alibaba Model Studio** — примерно 1 000 000 токенов на каждую
  модель, бесплатно 90 дней с активации, только регион Singapore, карта для
  старта не нужна;
* **OpenRouter, модели с суффиксом `:free`** — 20 запросов в минуту и 50 в
  сутки при нулевом балансе, карта не нужна. Список бесплатных моделей меняется,
  поэтому модель задаётся настройкой; на 2026-09-06 бесплатных **Qwen** там не
  было, зато были другие (`z-ai/glm-5.2:free`, `nvidia/nemotron-*:free`).

Локальная модель нужна только если хочется полностью убрать внешние квоты:

```bash
ollama pull qwen2.5:7b-instruct
```

## Бренд

`config/brand.yaml` — единственное место, где живут название, обещание
читателю, правила тона и подпись на карточках. Оттуда их берут и карточки, и
промпты генерации: канал должен звучать одинаково независимо от того, писал ли
пост человек или модель.

Менять этот файл — значит менять канал целиком, в этом и смысл.

## Где это крутится

Конвейеру не нужна включённая машина: в `.github/workflows/` лежат три задачи.

| Задача | Когда | Что делает |
|---|---|---|
| `publish` | каждый час | `publish-due` — сам решает, нужен ли пост сейчас |
| `research` | раз в сутки | опрос источников, кластеризация, Topic Score |
| `tests` | на push и PR | ruff и unit-тесты |

Секреты живут в Secrets репозитория, переключатели `PUBLISH_MODE` и
`AUTO_PUBLISH_ENABLED` — в Variables, чтобы остановить публикацию можно было
одним кликом, не трогая код.

**Сначала проверка связи.** У задачи `publish` есть ручной запуск с флагом
`preflight_only`: он выполняет `db-status` и `max-check` и ничего не публикует.
Это не формальность — MAX Bot API мы вызывали только с российского адреса, а
runner GitHub находится за рубежом. Если доступа оттуда нет, выяснить это нужно
до переезда, а не в день первой публикации.

## Команды

```bash
uv run python -m channel_factory.cli publish-plan --days 3
```

Слоты на ближайшие дни, какие заняты, и сколько отобранных тем в запасе.

```bash
uv run python -m channel_factory.cli publish-preview --limit 3
```

Как будут выглядеть посты. Ничего не отправляет и не пишет в базу.

```bash
uv run python -m channel_factory.cli publish-due
```

Опубликовать в открытый слот, если он ещё пуст. Это и есть команда для
планировщика ОС.

```bash
uv run python -m channel_factory.cli publish-log --limit 15
```

История публикаций, включая симуляции и заблокированные попытки.

## Запуск по расписанию (Windows)

Задача, которая раз в час зовёт `publish-due` — команда сама решит, нужен ли
пост именно сейчас:

```bash
schtasks /create /tn "channel-factory publish" /sc hourly /st 09:05 /tr "cmd /c cd /d C:\dev\yan-channel-factory && uv run python -m channel_factory.cli publish-due >> logs\publish.log 2>&1"
```

Отдельная задача раз в сутки пополняет запас тем:

```bash
schtasks /create /tn "channel-factory research" /sc daily /st 07:00 /tr "cmd /c cd /d C:\dev\yan-channel-factory && uv run python -m channel_factory.cli research-poll && uv run python -m channel_factory.cli research-cluster && uv run python -m channel_factory.cli score-topics"
```

## Запас тем

Три поста в день — 90 тем за месяц. `publish-plan` показывает, сколько
отобранных тем ещё не опубликовано. Если запас кончается, слот честно
пропускается с причиной `NO_TOPIC`: выдумывать темы конвейер не станет.
