# Конвейер публикаций: три поста в день

Цель конвейера — держать ритм канала: три поста в сутки без ручной работы.
Всё звено работает **бесплатно**: MAX Bot API без тарифов, картинки рисуются
локально, текст пишет либо локальная модель, либо бесплатный tier Gemini.

## Путь одного поста

```
research-poll → research-cluster → score-topics → publish-due
   источники      события            Topic Score    слот → пост
```

1. **research** собирает факты из whitelist-источников и схлопывает их в
   события (кластеры), считает Topic Score и отбирает лучшие (`SELECTED`).
2. **drafting** собирает скелет поста: заголовок, одна фактическая фраза из
   полей, которые мы извлекли сами, ссылка на первоисточник — и **маркер** на
   месте оригинального разбора.
3. **generation (PHASE 5)** пишет разбор и русский заголовок. Пересказ
   источника прямо запрещён промптом: это и бесполезно читателю, и плагиат.
4. **cards (PHASE 6)** рисует картинку 1200×630 локально через Pillow.
5. **publish-due** проверяет, открыт ли слот и не занят ли он, и публикует.

Скелет без разбора публиковать нельзя: `is_publishable` = False, издатель
возвращает `BLOCKED`. Это осознанный тупик — лучше пропустить слот, чем
выложить полуфабрикат.

## Слоты и идемпотентность

Расписание не хранится в таблице. Слот считается занятым, если в его окне уже
есть публикация — источник правды тот же `publications`. Отсюда свойства:

* `publish-due` можно звать хоть каждые пять минут: в слот уйдёт максимум один
  пост;
* пропущенный запуск не теряет слот — окно `PUBLISH_SLOT_WINDOW_MINUTES`
  (по умолчанию 180 минут) даёт время наверстать;
* «симулированные» посты (`DRY_RUN`) тоже занимают слот, иначе репетиция вела
  бы себя не так, как боевой режим.

Настройки:

```
PUBLISH_SLOTS=09:00,14:00,19:00
PUBLISH_SLOT_WINDOW_MINUTES=180
```

## Два выключателя

```
PUBLISH_MODE=DRY_RUN        # DRY_RUN | LIVE
AUTO_PUBLISH_ENABLED=false  # главный рубильник
```

Оба по умолчанию выключены. Чтобы посты реально уходили в канал, нужно
`PUBLISH_MODE=LIVE` **и** `AUTO_PUBLISH_ENABLED=true`. В `DRY_RUN` конвейер
проходит весь путь, пишет строку в `publications` и не отправляет ничего.

## Кто пишет текст

| Бэкенд | Стоимость | Что уходит наружу |
|---|---|---|
| Ollama (локально) | бесплатно | ничего |
| Gemini free tier | бесплатно | заголовок, вендор, продукт, версия |
| нет бэкенда | — | посты остаются скелетами и не публикуются |

Выбор автоматический: если локальный Ollama отвечает и модель скачана — берётся
он; иначе Gemini, если задан ключ. Настройки: `OLLAMA_BASE_URL`, `OLLAMA_MODEL`.

Чтобы перейти на локальную модель:

```bash
ollama pull qwen2.5:7b-instruct
```

Пока Ollama не установлен, работает Gemini. У бесплатного tier есть суточная
квота и он периодически отвечает `429`/`500` — на трёх постах в день это
терпимо, но локальная модель снимает зависимость полностью.

## Команды

```bash
uv run python -m channel_factory.cli publish-plan --days 3
```

Слоты на ближайшие дни, какие заняты, и сколько отобранных тем в запасе.

```bash
uv run python -m channel_factory.cli publish-preview --limit 3
```

Как будут выглядеть посты. Ничего не отправляет и не пишет в базу.

```bash
uv run python -m channel_factory.cli publish-due
```

Опубликовать в открытый слот, если он ещё пуст. Это и есть команда для
планировщика ОС.

```bash
uv run python -m channel_factory.cli publish-log --limit 15
```

История публикаций, включая симуляции и заблокированные попытки.

## Запуск по расписанию (Windows)

Задача, которая раз в час зовёт `publish-due` — команда сама решит, нужен ли
пост именно сейчас:

```bash
schtasks /create /tn "channel-factory publish" /sc hourly /st 09:05 /tr "cmd /c cd /d C:\dev\yan-channel-factory && uv run python -m channel_factory.cli publish-due >> logs\publish.log 2>&1"
```

Отдельная задача раз в сутки пополняет запас тем:

```bash
schtasks /create /tn "channel-factory research" /sc daily /st 07:00 /tr "cmd /c cd /d C:\dev\yan-channel-factory && uv run python -m channel_factory.cli research-poll && uv run python -m channel_factory.cli research-cluster && uv run python -m channel_factory.cli score-topics"
```

## Запас тем

Три поста в день — 90 тем за месяц. `publish-plan` показывает, сколько
отобранных тем ещё не опубликовано. Если запас кончается, слот честно
пропускается с причиной `NO_TOPIC`: выдумывать темы конвейер не станет.
