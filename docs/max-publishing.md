# Публикация в MAX

Адаптер для постинга в каналы MAX через официальный Bot API
(<https://dev.max.ru/docs-api>). Всё описанное здесь работает **бесплатно**:
у Bot API нет платных тарифов, оплачивать нужно только то, чего мы не делаем
(реклама, продвижение).

Адаптер сам по себе не пишет в базу — это делает `publishers/service.py`, куда
он подключён: каждая публикация, симуляция и заблокированная попытка попадает в
таблицу `publications`. Конвейер, который решает *что* и *когда* публиковать,
описан в [posting-pipeline.md](posting-pipeline.md).

## Что нужно один раз

1. **Профиль.** Бота может создать владелец подтверждённого профиля
   организации, ИП или самозанятого (требование платформы, не наше).
2. **Бот и токен.** Бот создаётся в приложении MAX через `@MasterBot`,
   он же выдаёт токен. Токен — это пароль: он живёт только в `.env`.
3. **Канал.** Бот добавляется в канал **администратором**. Без прав
   администратора канал для бота недоступен, и `max-check` это покажет.
4. **`chat_id` канала.** Метода «получить список каналов» в API больше нет
   (`GET /chats` не поддерживается с июня 2026). Идентификатор узнаётся из
   событий: см. `max-discover` ниже.

## Настройка `.env`

```
MAX_BOT_TOKEN=<токен от MasterBot>
MAX_CHAT_ID=<id канала>
```

Необязательные: `MAX_API_BASE_URL`, `MAX_REQUEST_TIMEOUT`, `MAX_CA_BUNDLE`
(см. ниже про сертификат).

## Хост API и сертификат

Документация называет базовым хостом `platform-api2.max.ru`, но он отдаёт
сертификат, выпущенный **Russian Trusted Sub CA** (Минцифры). Этого корневого
центра нет ни в `certifi`, ни в хранилище Windows, поэтому любой запрос туда
падает с `CERTIFICATE_VERIFY_FAILED` до тех пор, пока корень не установлен.

Тот же API отвечает на `platform-api.max.ru` (и на `botapi.max.ru`) с обычным
доверенным сертификатом — проверено, ответы идентичны. Поэтому по умолчанию
используется `https://platform-api.max.ru`.

Если нужен именно хост из документации:

```
MAX_API_BASE_URL=https://platform-api2.max.ru
MAX_CA_BUNDLE=C:\path\to\russian-trusted-root.pem
```

`MAX_CA_BUNDLE` — PEM-файл с корневым сертификатом Минцифры. Он добавляет
доверие **только для запросов этого адаптера**; это сознательно лучше, чем
установить такой корень в системное хранилище, где он начнёт действовать на весь
TLS-трафик машины. Проверка сертификата при этом остаётся включённой — режима
«без проверки» в адаптере нет.

## Команды

```bash
uv run python -m channel_factory.cli max-discover --wait 30
```

Long polling `GET /updates`: показывает `chat_id` из свежих событий бота.
Добавьте бота в канал администратором или напишите там сообщение — и запустите
команду. Если событий нет, команда честно печатает `NO DATA`, а не выдумывает id.

```bash
uv run python -m channel_factory.cli max-check
```

Проверка перед первым постом: чей это токен (`GET /me`), что за канал
(`GET /chats/{id}`), и есть ли у бота права на публикацию
(`GET /chats/{id}/members/me`). Если права выяснить не удалось, так и пишется —
`UNKNOWN`, а не «можно».

```bash
uv run python -m channel_factory.cli max-post "Текст поста" --dry-run
```

`--dry-run` собирает тело запроса и показывает его, ничего не отправляя и не
загружая. Работает даже без токена — удобно смотреть, как ляжет текст.

```bash
uv run python -m channel_factory.cli max-post "Текст поста"
```

Реальная публикация. Перед отправкой команда печатает предпросмотр и просит
подтверждение (`--yes` — пропустить вопрос, для скриптов). По умолчанию сначала
выполняется та же проверка, что и в `max-check` (`--skip-check` — отключить).

Опции `max-post`:

| Опция | Назначение |
|---|---|
| `--text-file FILE` | взять текст из UTF-8 файла вместо аргумента |
| `--chat-id N` | канал, если он не тот, что в `.env` |
| `--media FILE` | вложить локальный файл, можно несколько раз |
| `--image-url URL` | вложить картинку по ссылке (для картинок API это разрешает) |
| `--format markdown\|html\|plain` | как MAX отрисует текст |
| `--silent` | без уведомления подписчикам |
| `--no-link-preview` | не показывать карточку ссылки |
| `--dry-run` | собрать запрос и показать, ничего не отправляя |
| `--skip-check` | не делать предварительную проверку |
| `--yes` | не спрашивать подтверждение |

```bash
uv run python -m channel_factory.cli max-edit-post <mid> "Новый текст"
```
```bash
uv run python -m channel_factory.cli max-delete-post <mid>
```

`mid` — идентификатор сообщения, который печатает `max-post`.

## Какие посты можно публиковать

| Что | Ограничение платформы |
|---|---|
| Текст | до 4000 символов на пост |
| Разметка | `markdown` или `html` |
| Картинка | JPG, PNG, GIF, TIFF, BMP, HEIC; до 50 МБ и 7680×7680 |
| Видео | MP4, MOV, MKV, WEBM; до 250 МБ |
| Аудио | MP3, WAV, M4A; до 256 МБ или 60 минут |
| Файл | обычные форматы (PDF, DOC, TXT…); до 4 ГБ |
| Уведомление | у каналов API требует `notify: true` |

Текст длиннее лимита **не режется молча**: команда останавливается и говорит,
на сколько символов вы вышли. Разбивать пост на части — осознанное решение
автора, а не побочный эффект отправки.

## Лимиты и повторы

* 2 сообщения в секунду в один канал — клиент сам выдерживает интервал.
* 30 запросов в секунду на весь API.
* `429` и `5xx` повторяются с экспоненциальной задержкой (учитывается
  `Retry-After`). Ошибки `4xx`, кроме описанной ниже, не повторяются: смысла
  нет, а дубль поста — цена ошибки.
* Отправка сразу после загрузки большого файла может не пройти, пока платформа
  его обрабатывает. Документация советует подождать и повторить — адаптер это и
  делает, но только для этого случая.

## Как устроено внутри

```
publishers/
    base.py        PublishRequest, MediaItem, PublishResult — контракт платформ
    max/
        client.py     HTTP: авторизация, повторы, троттлинг, разбор ошибок
        adapter.py    правила публикации: валидация, вложения, preflight
        discovery.py  поиск chat_id через GET /updates
        factory.py    сборка клиента и издателя из настроек
```

Загрузка файла — три шага из документации: `POST /uploads?type=…` даёт URL,
файл уходит туда `multipart/form-data` полем `data`, полученный токен
подставляется во вложение. Токен вложения приходит в разном месте в зависимости
от типа файла, поэтому клиент принимает все три варианта, описанные в документации
(ответ `/uploads`, ответ загрузки, параметр в URL).

Токен бота не уходит на хост загрузки: для файлов используется отдельный
HTTP-клиент без заголовка `Authorization`.

## Чего адаптер пока не делает

* Не читает статистику постов (`MessageStat` в ответе API) — отдельная задача
  вместе с аналитикой публикаций.
* Не работает с комментариями, кнопками (`keyboard`), опросами и вебхуками.
* Не постит в Telegram — это отдельный адаптер.
