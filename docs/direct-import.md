# Импорт рыночных выгрузок

Документ описывает, как файл превращается в строки PostgreSQL, и какие решения
приняты по спорным местам. Правила реализованы в
`src/channel_factory/direct/` и покрыты тестами в `tests/`.

## Конвейер

```
XLSX/CSV
  -> SHA-256 файла
  -> проверка «уже импортирован?»       (skip, если да и нет --force)
  -> запись direct_imports (RUNNING)     — commit сразу, чтобы сбой остался в истории
  -> чтение таблицы (openpyxl / csv)
  -> маппинг колонок (config/direct_columns.yaml)
  -> нормализация + валидация построчно
  -> дедупликация каналов
  -> batch insert строк и снимков
  -> финализация direct_imports (SUCCESS / PARTIAL / FAILED)
```

## Чтение файла

Значения читаются **как есть**, без приведения типов: интерпретация — задача
слоя нормализации, а исходное значение обязано остаться восстановимым.

* XLSX — `openpyxl` в режиме `read_only` + `data_only`.
* CSV — кодировки пробуются по очереди: `utf-8-sig`, затем `cp1251`;
  разделитель определяется `csv.Sniffer` с откатом на подсчёт `;`, `,`, `\t`.
* Заголовком считается первая строка (из первых 20), где есть минимум 2
  непустых ячейки — это пропускает титульные строки над «настоящей» шапкой.
* Номера строк соответствуют номерам в Excel, чтобы отчёт об ошибке можно было
  открыть и глазами.

## Маппинг колонок

Названия колонок дрейфуют между выгрузками, поэтому соответствия живут в
`config/direct_columns.yaml`, а не в коде. Добавление нового формата выгрузки не
должно требовать изменения кода — только алиасов.

Сопоставление идёт по нормализованному заголовку: нижний регистр, `ё` → `е`,
пунктуация убрана, пробелы схлопнуты. Поэтому `«Подписчики, чел.»` и
`«подписчики чел»` попадают в одно поле.

* Первая подходящая колонка выигрывает, дубликаты фиксируются в
  `direct_imports.column_mapping` (видно в `show-import`).
* Не распознанные колонки не выбрасываются: они попадают в
  `market_snapshots.extra` (JSONB).
* Отсутствие обязательного поля (`channel_name`) — фатальная ошибка импорта.

## Нормализация чисел

Главная неоднозначность: `"1,240"` — это 1240 (разделитель разрядов) или 1.240
(десятичная запятая)? Ответ зависит от того, что мы читаем, поэтому парсер
получает флаг `prefer_thousands_group`:

| Поле | Правило | Пример |
|---|---|---|
| `subscribers`, `predicted_views` | запятая/точка = разряды (счётчики целые) | `1,240` → `1240` |
| `campaign_price` | запятая = разряды (цены крупные) | `15 000 ₽` → `15000` |
| `cpv`, `err` | запятая = десятичная (метрики точные) | `1,25` → `1.25` |

Дополнительно:

* пробелы-разделители (обычный, NBSP, узкий NBSP, тонкий) убираются;
* если в числе есть и `,` и `.`, десятичным считается **последний** из них;
* `ERR`: `"24,7%"` → `0.247`; значение больше 1 без знака `%` трактуется как
  проценты и **сопровождается предупреждением**, а не молча;
* ERR выше 1 (100%) допустим — просмотры могут превышать число подписчиков;
  выше 5 фиксируется предупреждение;
* валюта распознаётся по символу/слову (`₽`, `руб.`, `$`, `€`).

Даты принимаются как объекты Excel или в форматах ISO, `ДД.ММ.ГГГГ`,
`ДД/ММ/ГГГГ`, `ГГГГ/ММ/ДД`, `ДД-ММ-ГГГГ`, `ДД.ММ.ГГ`. Неоднозначный
американский `ММ/ДД/ГГГГ` намеренно не поддерживается — лучше явная ошибка, чем
тихо перепутанные месяц и день.

## Политика ошибок

| Ситуация | Реакция |
|---|---|
| Нет обязательной колонки | Импорт `FAILED`, ничего не записано |
| Файл нечитаем / нет строк данных | Импорт `FAILED` |
| Пустое название канала | Строка `REJECTED`, импорт продолжается |
| Не распознано число/дата | Предупреждение, поле `NULL`, `raw_data` сохранён |
| Отрицательное значение метрики | Предупреждение, поле `NULL` |
| Значение похоже на `@handle`, а не URL | Предупреждение, используется как handle |

Одна плохая ячейка никогда не стоит целой строки. Отклонённые строки хранятся
вместе с их ошибками — данные не пропадают молча.

## Дедупликация каналов

Один канал в нескольких выгрузках обязан стать **одной** строкой
`market_channels` с несколькими снимками, иначе статистика по нише поедет.

Ключ идентичности (`dedupe_key`) строится по убыванию надёжности:

1. `ext:<external_id>` — явный ID платформы;
2. `handle:<username>`;
3. `url:<host><path>` — в нижнем регистре;
4. `name:<slug>` — последний вариант, если ничего другого нет.

Уникальность — по паре `(platform, dedupe_key)`.

Внутри одного файла повтор `(канал, дата)` не создаёт второй снимок: остаётся
первое вхождение, остальные помечаются предупреждением.

## Идемпотентность

Файл опознаётся по SHA-256 всего содержимого.

* Повторный импорт того же файла → `SKIPPED` со ссылкой на прошлый прогон.
* `--force` → **новый** прогон импорта; старый не перезаписывается, история
  импортов append-only.
* Прогоны со статусом `FAILED` не считаются «уже импортированными», поэтому
  после исправления файла его можно импортировать без `--force`.

## Историчность

`market_snapshots` только дополняется. Метрика никогда не обновляется на месте,
поэтому история канала (и ниши) остаётся восстановимой:

```
market_channels: AI Tools Daily
  market_snapshots: 2026-09-01 -> 12 500 подписчиков
  market_snapshots: 2026-10-01 -> 18 900 подписчиков
```

`first_seen_date` / `last_seen_date` у канала расширяются по мере поступления
новых снимков.
